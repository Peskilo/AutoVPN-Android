# AutoVPN — VPN-клиент для Android

AutoVPN — VPN/прокси-клиент для Android на ядре **sing-box** (libbox). Добавьте ссылку на
подписку, выберите сервер, нажмите «Подключить». Kotlin, Jetpack Compose
(Material 3), coroutines/Flow, Hilt, Room, DataStore, OkHttp.

Работает с панелями [Remnawave](https://docs.rw/) и с обычными подписками из
ссылок на серверы (VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC).


## Что умеет

- **Подписки:** импорт по URL, ссылке на сервер или QR-коду; периодическое
  автообновление по интервалу провайдера; показываются трафик, срок действия и
  ссылки на поддержку от провайдера. Импортируемые данные считаются
  недоверенными (лимиты размера, типизированные ошибки разбора), а неудачное
  обновление никогда не перезаписывает рабочую подписку.
- **Серверы:** поиск, фильтры, избранное, проверка задержки, режим «Авто».
- **Маршрутизация:** всё через прокси, обход для российских сайтов или проксирование
  только заблокированных; VPN для выбранных приложений; обход локальной сети;
  режим и upstream DNS; свои правила.
- **Соединение:** живой график скорости, суммарный трафик, число соединений,
  проверки состояния (проверка IP и DNS), переподключение при смене сети,
  восстановление после перезагрузки, плитка в быстрых настройках, подсказки по Always-on VPN.
- **Приватность:** HWID отправляется провайдеру только после явного согласия;
  экспорт диагностики очищен от секретов; секреты (URL подписок, UUID, пароли)
  не попадают в логи.
- **Приложение:** английский и русский, светлая/тёмная/системная тема, динамические цвета.

Интерфейс показывает только то, что сообщает конечный автомат соединения;
никакого «декоративного» статуса «Подключено» нет.

## Статус

В активной разработке. Клиент работает и используется на телефоне автора, но не
закончен и не опубликован в Google Play.
Ещё предстоит: онбординг при первом запуске, опубликованная политика
конфиденциальности и решение по лицензии на арт/маскота.

Проверено на физическом телефоне (Android 16) и на эмуляторе; сборка и JVM-тесты
(парсеры, классификатор, редактирование секретов, конечный автомат) запускаются в CI.
Всё, что затрагивает VPN, проверяется на устройстве, а не только юнит-тестами.

## Архитектура

`ConnectionManager` владеет конечным автоматом соединения и единственный, с кем
общается UI. Типы sing-box/libbox спрятаны за границей `VpnEngine` в
`core.engine.singbox`; замена ядра не затронула бы UI. Подписки проходят
конвейер: загрузка → классификация → разбор → проверка → сохранение.

## Сборка

```bash
./gradlew assembleDebug   # сначала скачивает и проверяет по контрольной сумме libbox.aar
./gradlew test            # JVM-тесты (парсеры, классификатор, редактирование секретов)
./gradlew lint
```

libbox AAR скачивается при сборке из зафиксированного релиза `singbox-android/libbox`
на GitHub и сверяется с SHA-256, записанным в `app/build.gradle.kts`.
Версия ядра лежит в `gradle/libs.versions.toml` как `vpnCore`.

Требования (взяты из файлов сборки):

- **JDK 25 для запуска Gradle.** `gradle/gradle-daemon-jvm.properties` фиксирует
  демон на Java 25 (`toolchainVersion=25`), а `settings.gradle.kts` подключает
  резолвер Foojay, поэтому отсутствующий JDK 25 подтянется автоматически. CI
  (`.github/workflows/android-ci.yml`) использует Temurin 25. Байткод собирается
  под Java 11 (`compileOptions` в `app/build.gradle.kts`).
- Gradle 9.5.0 (wrapper, с контрольной суммой), AGP 9.3.3, Kotlin 2.2.10.
- Android SDK platform 37 (`compileSdk`/`targetSdk` 37), `minSdk` 26.
- Доступ в сеть при первой сборке, чтобы скачать libbox AAR.

Не запускайте Gradle-задачи `connected*` на физическом телефоне: они удаляют приложение и стирают его данные.

## Структура

```
app/src/main/java/dev/typenil/vpnclient/
├── core/
│   ├── common/log/          # SecureLog + Redactor (no secrets in logs)
│   ├── engine/              # VpnEngine boundary (no libbox types)
│   │   └── singbox/         # libbox adapter, platform bridge, config compiler
│   ├── subscription/        # fetch → classify → parse pipeline
│   │   └── model/           # ProxyNode, SubscriptionProfile, errors
│   └── vpn/                 # ClientVpnService, ConnectionManager, state machine
├── data/                    # Room db, DataStore settings, NodeConfigProvider
├── di/                      # Hilt modules
└── ui/                      # Compose screens + viewmodels
```
